# ファイル別プログラム仕様書

## 1. `Main.js`

### 1.1 役割

Google Apps Script から直接呼ばれるエントリーポイントを定義するファイルです。外部トリガー、Web アプリの POST、手動セットアップから呼ばれる関数だけを配置し、実際の業務処理は UseCase 層へ委譲します。

### 1.2 公開関数

#### `runScheduler()`

5 分ごとの時間主導トリガーから呼ばれる関数です。`SchedulerUseCase.run()` を呼び、外出予定の確認と LINE 通知制御を実行します。

入力はありません。戻り値もありません。例外処理は `SchedulerUseCase.run()` 側で行います。

#### `doPost(e)`

GAS Web アプリの POST リクエストを受ける関数です。LINE Webhook からのイベントを `WebhookUseCase.handle(e)` に渡します。

入力 `e` は GAS のイベントオブジェクトです。`e.postData.contents` に LINE Webhook の JSON 本文、`e.parameter.webhook_token` に任意の検証トークンが入る想定です。

戻り値は `ContentService.createTextOutput()` で作られるテキストレスポンスです。正常時は `ok`、認可失敗時は `forbidden`、例外時は `error` が返ります。

#### `sendHealthCheck()`

日次の正常稼働通知トリガーから呼ばれる関数です。`HealthCheckUseCase.send()` を呼び出します。

#### `setupTriggers()`

初期セットアップ用の手動実行関数です。次の処理を行います。

- `ConfigRepository.bootstrapDefaults()` により任意設定の既定値を Script Properties に投入する。
- `runScheduler` の既存トリガーを削除し、5 分ごとのトリガーを作成する。
- `sendHealthCheck` の既存トリガーを削除し、毎日 8 時のトリガーを作成する。
- セットアップ完了ログを出力する。

### 1.3 内部オブジェクト

#### `MainEntryPoint.recreateTimeTrigger_(functionName, createFn)`

指定した関数名の既存トリガーをすべて削除し、渡された作成関数で新しい時間主導トリガーを作ります。

同じ関数に対するトリガーが重複しないようにするための補助関数です。

### 1.4 依存先

- `SchedulerUseCase`
- `WebhookUseCase`
- `HealthCheckUseCase`
- `ConfigRepository`
- `LogModule`
- `ScriptApp`

## 2. `SchedulerUseCase.js`

### 2.1 役割

5 分ごとに実行される外出判定と通知制御の中心ファイルです。設定読み込み、センサー取得、予定取得、状態読み書き、外出判定、通知送信、古い状態の掃除をまとめて制御します。

### 2.2 公開オブジェクト

#### `SchedulerUseCase.run()`

スケジューラー処理全体を実行します。

処理手順は次の通りです。

1. `LogModule.createTraceId()` でトレース ID を作成する。
2. 現在時刻を取得する。
3. `ConfigRepository.load()` で設定値を読み込む。
4. `fetchSensor_()` で Nature Remo の最新人感検知情報を取得する。
5. センサー取得に失敗した場合は、その回の処理を終了する。
6. `CalendarGateway.listTodayOutingEvents(config, now)` で当日の外出予定を取得する。
7. 取得した外出予定をログに出す。
8. 各予定に対して `processEvent_()` を実行する。
9. `StateRepository.cleanupOldStates(now, 7)` で 7 日より古い予定状態を削除する。
10. 例外が発生した場合は `error` ログを出す。

### 2.3 内部関数

#### `fetchSensor_(config, traceId)`

Nature Remo API から最新人感検知情報を取得します。成功時はセンサー情報を返し、失敗時は `sensor` カテゴリのエラーログを出して `null` を返します。

返却されるセンサー情報は、`fetchedAt`、`fetchedAtIso`、`lastDetectedAt`、`lastDetectedAtIso`、`deviceId`、`deviceName`、`value` を持つオブジェクトです。

#### `processEvent_(event, sensor, config, now, traceId)`

外出予定 1 件に対して、監視対象かどうか、外出済みかどうか、通知すべきかどうかを判定します。

処理仕様は次の通りです。

- `DeparturePolicy.isInMonitoringWindow()` が `false` の場合は処理しない。
- `StateRepository.load(event)` で予定状態を取得する。
- `DeparturePolicy.isDepartedConfirmed()` が `true` の場合は `markDeparted_()` を実行して終了する。
- `NotificationPolicy.decide()` で通知判断を行う。
- 判断結果が `stop` の場合は状態を `stopped` にして保存する。
- 判断結果が `skip` の場合はログだけ出して終了する。
- 判断結果が `send` の場合は `sendStageNotification_()` で LINE 通知を送る。

#### `markDeparted_(event, state, config, now, traceId)`

外出が確認された予定を `departed` 状態にします。既に `departed` の場合は何もしません。

状態保存後、静穏時間外であれば `MessageTemplate.buildDepartedMessage(event)` で本文を作り、`LineGateway.pushText()` で外出確認メッセージを送信します。静穏時間中は状態だけ更新し、通知は抑制します。

#### `sendStageNotification_(event, state, stage, config, now, traceId)`

通知段階に応じた催促メッセージを送信します。送信成功時は次の状態更新を行います。

- `status` を `notifying` にする。
- `currentStage` を送信した段階にする。
- `noticeCount` を 1 増やす。
- `lastNoticeAtIso` を現在時刻にする。
- 状態を保存する。
- `LATEST_NOTIFIED_EVENT_ID` に対象予定 ID を保存する。

LINE API 送信に失敗した場合は `line` カテゴリのエラーログを出します。

- `ConfigRepository`
- `NatureGateway`
- `CalendarGateway`
- `StateRepository`
- `DeparturePolicy`
- `NotificationPolicy`
- `NotificationStage`
- `EventStatus`
- `MessageTemplate`
- `LineGateway`
- `LogModule`

## 3. `WebhookUseCase.js`

### 3.1 役割

LINE Webhook から送られたユーザー返信を処理し、直近に通知した予定の状態を更新します。

### 3.2 公開関数

#### `WebhookUseCase.handle(e)`

Webhook リクエストを処理します。

処理手順は次の通りです。

1. トレース ID を作成する。
2. 設定値を読み込む。
3. `isAuthorized_()` で Webhook トークンを検証する。
4. リクエスト本文を JSON として解析する。
5. `body.events` の各イベントを `handleEvent_()` に渡す。
6. 正常終了時は `ok` を返す。
7. 認可失敗時は `forbidden` を返す。
8. 例外発生時は `error` ログを出し、`error` を返す。

### 3.3 内部関数

#### `isAuthorized_(e, config)`

`LINE_WEBHOOK_TOKEN` が設定されていない場合は常に `true` を返します。設定されている場合は、リクエストパラメータ `webhook_token` と一致する場合のみ `true` を返します。

#### `handleEvent_(event, config, traceId)`

LINE Webhook イベント 1 件を処理します。テキストメッセージ以外は無視します。

認識できるコマンドの場合、`LATEST_NOTIFIED_EVENT_ID` から直近通知予定 ID を取得し、該当 state を読み込みます。状態がない場合は「対象の通知予定が見つかりませんでした。」と返信します。

状態がある場合は `applyCommand_()` で状態を更新し、保存してから LINE に返信します。

#### `normalizeCommand_(text)`

ユーザー入力をコマンドへ正規化します。前後空白を削除し、英字は大文字化します。

認識する値は次の通りです。

- `OK` -> `OK`
- `スヌーズ` -> `SNOOZE`
- `キャンセル` -> `CANCEL`

それ以外は `null` を返します。

#### `applyCommand_(command, state, config, now)`

コマンドに応じて状態を更新し、返信テキストを返します。

- `OK`: `snoozeUntilIso` を現在時刻から `SNOOZE_MINUTES` 分後にし、`status` を `snoozing` にする。
- `SNOOZE`: `OK` と同じ状態更新を行う。
- `CANCEL`: `cancelled` を `true` にし、`status` を `cancelled` にする。

#### `replySafe_(config, replyToken, text, traceId)`

LINE の reply API で返信します。`replyToken` がない場合は何もしません。返信中の例外は握りつぶさず、`line_reply` カテゴリのエラーログとして記録します。

#### `textOutput_(text)`

GAS Web アプリ用のテキストレスポンスを作成します。

### 3.4 依存先

- `ConfigRepository`
- `StateRepository`
- `LineGateway`
- `EventStatus`
- `LogModule`
- `ContentService`

## 4. `HealthCheckUseCase.js`

### 4.1 役割

日次の正常稼働通知を LINE に送信します。トリガーが動いていること、LINE API 送信が可能であることを簡易的に確認するための UseCase です。

### 4.2 公開関数

#### `HealthCheckUseCase.send()`

設定値を読み込み、`HEALTH_CHECK_ENABLED` が `true` の場合のみ正常稼働メッセージを送信します。本文は `MessageTemplate.buildHealthCheckMessage(now)` で生成します。

`HEALTH_CHECK_ENABLED` が `false` の場合は送信せず、無効化されていることをログに記録します。例外発生時は `health` カテゴリのエラーログを出します。

### 4.3 依存先

- `ConfigRepository`
- `MessageTemplate`
- `LineGateway`
- `LogModule`

## 5. `DomainModule.js`

### 5.1 役割

システムの業務ルールを定義するファイルです。外部 API や GAS サービスに直接依存しない、状態・外出判定・通知判定のロジックを持ちます。

### 5.2 定数

#### `EventStatus`

予定状態を表す列挙値です。

- `NOT_DEPARTED`: 外出未確認の初期状態。
- `NOTIFYING`: 通知中。
- `SNOOZING`: スヌーズ中。
- `DEPARTED`: 外出確認済み。
- `CANCELLED`: キャンセル済み。
- `STOPPED`: 最大通知回数到達などで停止済み。

#### `NotificationStage`

通知段階を表す数値です。

- `NONE`: 通知なし。
- `PREPARE`: 第1段階、準備リマインド。
- `DEPARTURE`: 第2段階、出発催促。
- `WARNING`: 第3段階、開始時刻到達後の警告。
- `REPEAT_WARNING`: 第4段階、繰り返し警告。

### 5.3 `EventStateFactory`

#### `create(event)`

予定情報から初期状態を作ります。初期状態では `status` は `not_departed`、`currentStage` は `NONE`、`noticeCount` は `0`、スヌーズや外出確認時刻は `null` です。

#### `mergeEvent(state, event)`

保存済み state に最新の予定タイトルと開始時刻を反映します。Google Calendar 側で予定名や開始時刻が変わった場合にも、保存済み state の表示情報を更新できます。

### 5.4 `DeparturePolicy`

#### `isDepartedConfirmed(event, sensorContext, config)`

Nature Remo の最新人感検知時刻をもとに、外出済みとみなせるかを返します。

`sensorContext` または `lastDetectedAt` が存在しない場合は `false` です。最新検知時刻が監視開始以降、API 取得時刻以前、かつ鮮度条件内である場合に `true` になります。

#### `getMonitorStart(event, config)`

監視開始時刻を返します。計算式は、予定開始時刻から `NOTICE_STAGE1_MIN_BEFORE` 分前です。

#### `isInMonitoringWindow(now, event, config)`

現在時刻が監視対象時間内かを返します。監視終了は、予定開始時刻から `NOTICE_REPEAT_MINUTES * NOTICE_MAX_COUNT` 分後です。

#### `isSensorFresh_(sensorContext, config, now)`

最新検知時刻が `SENSOR_FRESHNESS_MINUTES` 分以内か判定します。

### 5.5 `NotificationPolicy`

#### `decide(now, event, state, config)`

通知可否を判断し、`NotificationDecision` を返します。

戻り値は `{ action, stage, reason }` 形式です。`action` は `send`、`skip`、`stop` のいずれかです。

判定の優先順位は、終了状態、静穏時間、スヌーズ、最大通知回数、通知段階、クールダウンの順です。

#### `getDueStage_(minutesUntilStart, state, config)`

予定開始までの残り分数から通知段階を決定します。

- `minutesUntilStart <= -NOTICE_REPEAT_MINUTES`: `REPEAT_WARNING`
- `minutesUntilStart <= 0`: `WARNING`
- `minutesUntilStart <= NOTICE_STAGE2_MIN_BEFORE`: `DEPARTURE`
- `minutesUntilStart <= NOTICE_STAGE1_MIN_BEFORE`: `PREPARE`
- それ以外: `NONE`

#### `canSendForStage_(now, state, stage, config)`

同じ段階を重複送信しないための判定を行います。第1から第3段階は、現在段階より進んだ場合のみ送信できます。繰り返し警告は、最終通知から `NOTICE_REPEAT_MINUTES` 分以上経過していれば送信できます。

#### `isQuietHours(now, startText, endText)`

現在時刻が静穏時間内か判定します。`22:00` から `07:00` のように日付をまたぐ時間帯にも対応します。開始時刻と終了時刻が同じ場合、静穏時間なしとして `false` を返します。

#### `parseTimeMinutes_(text)`

`HH:mm` 形式の文字列を 0:00 からの分数に変換します。

### 5.6 `NotificationDecision`

通知判断の戻り値を作るファクトリです。

- `send(stage)`: 送信判断を返す。
- `skip(reason)`: スキップ判断を返す。
- `stop(reason)`: 停止判断を返す。

## 6. `ConfigRepository.js`

### 6.1 役割

Script Properties からアプリ設定を読み込み、UseCase 層へ設定オブジェクトとして渡す Repository です。UseCase 層より内側で `PropertiesService` を直接触らないための境界になります。

### 6.2 既定値

任意設定の既定値を `defaults` に持ちます。既定値の対象は、Google Calendar ID、外出キーワード、終日予定の扱い、センサー鮮度、通知タイミング、スヌーズ時間、静穏時間、ヘルスチェック有効化です。

### 6.3 公開関数

#### `load()`

Script Properties から設定値を読み込み、アプリ内部用の設定オブジェクトを返します。

必須キーは次の通りです。存在しない場合は例外を投げます。

- `NATURE_API_TOKEN`
- `LINE_CHANNEL_ACCESS_TOKEN`
- `LINE_TO_USER_ID`

任意キーは、未設定または空文字の場合に既定値が使われます。ただし `NATURE_DEVICE_ID`、`NATURE_DEVICE_NAME`、`LINE_WEBHOOK_TOKEN` は空文字が既定値です。

数値項目は `Number()` で変換されます。`SENSOR_FRESHNESS_MINUTES` は 0 より大きい必要があります。

#### `bootstrapDefaults()`

`defaults` に定義された任意設定値を Script Properties に投入します。既に値が存在するキーは上書きしません。初期セットアップ時に利用します。

### 6.4 内部関数

- `getRequired_(props, key)`: 必須値を取得し、未設定なら例外を投げる。
- `getOptional_(props, key, defaultValue)`: 任意値を取得し、未設定または空文字なら既定値を返す。
- `getNumber_(props, key)`: 数値として取得し、不正なら例外を投げる。
- `getPositiveNumber_(props, key)`: 0 より大きい数値として取得する。
- `parseCsv_(value)`: カンマ区切り文字列をトリム済み配列に変換する。
- `parseBoolean_(value)`: 文字列が `true` の場合のみ `true` を返す。

### 6.5 依存先

- `PropertiesService`

## 7. `CalendarModule.js`

### 7.1 役割

Google Calendar から当日の予定を取得し、外出通知の対象になる予定だけを抽出する Gateway です。

### 7.2 公開オブジェクト

#### `CalendarGateway.listTodayOutingEvents(config, now)`

指定日時の日付を基準に、0:00:00 から 23:59:59 までの予定を取得します。`now` が省略された場合は現在日時を使います。

`config.calendarId` が `primary` の場合は既定カレンダーを利用し、それ以外の場合は指定 ID のカレンダーを取得します。カレンダーが見つからない場合は例外を投げます。

取得した予定は `isOutingEvent_()` で外出予定だけに絞り、`toOutingEvent_()` でアプリ内部用データに変換して返します。

### 7.3 内部関数

#### `isOutingEvent_(event, config)`

Google Calendar の予定が外出予定か判定します。

判定条件は次の通りです。

- 終日予定で `config.includeAllDayEvent` が `false` の場合は対象外。
- 場所が空でない場合は対象。
- 場所が空の場合、タイトルまたは説明文に `config.outingKeywords` のいずれかが含まれれば対象。

#### `toOutingEvent_(event)`

Google Calendar の予定オブジェクトをアプリ内部用の `OutingEvent` に変換します。

返却項目は、`id`、`calendarEventId`、`title`、`description`、`location`、`start`、`end`、`isAllDay` です。

#### `buildEventStateId_(event)`

状態保存用 ID を作成します。形式は `<calendarEventId>_<startTimeIso>` です。これにより、同じ Google Calendar イベント ID でも開始時刻が異なる予定を別状態として扱えます。

### 7.4 テスト補助関数

#### `testCalendarModule()`

設定を読み込み、本日の外出予定数と予定名をログに出す手動確認用関数です。

### 7.5 依存先

- `CalendarApp`
- `ConfigRepository`

## 8. `NatureModule.js`

### 8.1 役割

Nature Remo Cloud API からデバイス情報を取得し、人感センサーの最新検知情報をアプリ内部用データとして返す Gateway です。

### 8.2 公開オブジェクト

#### `NatureGateway.listDevices(config)`

Nature Remo Cloud API の `/1/devices` に GET リクエストを送り、デバイス一覧を JSON 配列として返します。

HTTP ステータスが `200` 以外の場合は、レスポンス本文を含む例外を投げます。

#### `NatureGateway.fetchLastMotionDetectedAt(config)`

デバイス一覧を取得し、対象デバイスの `newest_events.mo` から最新の人感検知情報を返します。

複数の対象デバイスに人感イベントがある場合は、`created_at` が最も新しいイベントを採用します。人感イベントが見つからない場合、`lastDetectedAt` や `deviceId` などは `null` になります。

返却項目は、`fetchedAt`、`fetchedAtIso`、`lastDetectedAt`、`lastDetectedAtIso`、`deviceId`、`deviceName`、`value` です。

### 8.3 内部関数

#### `filterTargetDevices_(devices, config)`

対象デバイスを設定に従って絞り込みます。

- `config.natureDeviceId` があれば ID で絞る。
- ID がなく `config.natureDeviceName` があれば名前で絞る。
- どちらもなければ全デバイスを返す。

### 8.4 テスト補助関数

#### `testNatureModule()`

設定を読み込み、最新人感検知情報を JSON としてログに出す手動確認用関数です。

### 8.5 依存先

- `UrlFetchApp`
- `ConfigRepository`

## 9. `NotificationModule.js`

### 9.1 役割

LINE Messaging API への送信処理と、LINE に送るメッセージ本文の生成を担当します。

### 9.2 `LineGateway`

#### `pushText(config, text)`

LINE の push message API にテキストメッセージを送信します。送信先は `config.lineToUserId` です。

#### `replyText(config, replyToken, text)`

LINE の reply message API にテキストメッセージを送信します。Webhook の返信に使います。

#### `post_(url, config, body)`

LINE API へ POST リクエストを送る共通関数です。

送信ヘッダーは `Content-Type: application/json` と `Authorization: Bearer <LINE_CHANNEL_ACCESS_TOKEN>` です。HTTP ステータスが 2xx 以外の場合は例外を投げます。

成功時は `{ statusCode, body }` を返します。

### 9.3 `MessageTemplate`

#### `buildStageMessage(stage, event, now)`

段階通知の本文を生成します。本文には通知ラベル、予定名、予定開始時刻、現在時刻、外出動作未確認の説明を含みます。

#### `buildDepartedMessage(event)`

外出確認済みの本文を生成します。予定名と開始時刻を含みます。

#### `buildHealthCheckMessage(now)`

正常稼働通知の本文を生成します。確認時刻を `yyyy/MM/dd HH:mm` 形式で含みます。

#### `stageLabel_(stage)`

通知段階の数値を表示用ラベルに変換します。

#### `formatDate_(date, pattern)`

GAS のスクリプトタイムゾーンで日時を指定フォーマットに変換します。

### 9.4 依存先

- `UrlFetchApp`
- `Utilities`
- `Session`
- `NotificationStage`

## 10. `StateModule.js`

### 10.1 役割

予定ごとの通知状態を Script Properties に保存・読み込みする Repository です。5 分ごとのトリガー実行間で状態を引き継ぐために利用します。

### 10.2 定数

- `eventPrefix`: 予定状態キーの接頭辞。値は `EVENT_STATE_`。
- `latestNotifiedKey`: 直近通知予定 ID のキー。値は `LATEST_NOTIFIED_EVENT_ID`。

### 10.3 公開関数

#### `load(event)`

`EVENT_STATE_<event.id>` から状態を読み込みます。状態が存在しない場合は `EventStateFactory.create(event)` で初期状態を作ります。

読み込み後、`EventStateFactory.mergeEvent(state, event)` により予定タイトルと開始時刻を最新化します。

#### `loadById(eventId)`

予定 ID を指定して状態を読み込みます。存在しない場合は `null` を返します。Webhook が直近通知予定の状態を取得するときに使います。

#### `save(state)`

状態の `updatedAtIso` を現在時刻に更新し、`EVENT_STATE_<state.eventId>` に JSON 文字列として保存します。

#### `remove(eventId)`

指定予定 ID の状態を削除します。テスト補助や手動メンテナンスで利用できます。

#### `setLatestNotifiedEventId(eventId)`

直近に通知した予定 ID を `LATEST_NOTIFIED_EVENT_ID` に保存します。

#### `getLatestNotifiedEventId()`

直近に通知した予定 ID を取得します。

#### `cleanupOldStates(now, keepDays)`

Script Properties 内の `EVENT_STATE_` で始まるキーを走査し、`eventStartIso` が `keepDays` 日より古い状態を削除します。JSON 解析できない壊れた状態も削除します。

### 10.4 テスト補助関数

#### `testStateModule()`

テスト用予定を作り、状態の保存・読み込み・削除を確認する手動実行関数です。

### 10.5 依存先

- `PropertiesService`
- `EventStateFactory`
- `NotificationStage`

## 11. `LogModule.js`

### 11.1 役割

Cloud Logging で読みやすい構造化ログを出力します。JSON 文字列として `console.log` または `console.error` に出力します。

### 11.2 公開関数

#### `info(category, payload, traceId)`

情報ログを出力します。内部で `buildEntry_()` によりログエントリを作り、`console.log()` に JSON 文字列として渡します。

#### `error(category, payload, traceId)`

エラーログを出力します。内部で `buildEntry_()` によりログエントリを作り、`console.error()` に JSON 文字列として渡します。

#### `createTraceId()`

`Utilities.getUuid()` でトレース ID を生成します。

### 11.3 内部関数

#### `buildEntry_(category, payload, traceId)`

ログエントリを生成します。`traceId` が未指定の場合は新しい UUID を生成します。

返却項目は `timestamp`、`traceId`、`category`、`payload` です。

### 11.4 依存先

- `Utilities`
- `console`

## 12. `ConfigRepository.js` と各 UseCase の連携仕様

`ConfigRepository.load()` の返却値は、各 UseCase と Gateway の共通設定オブジェクトとして使われます。

主な利用箇所は次の通りです。

- `SchedulerUseCase`: 全設定を利用する。特に通知タイミング、静穏時間、センサー鮮度、LINE 送信設定を参照する。
- `WebhookUseCase`: Webhook トークン、スヌーズ分数、LINE 返信設定を参照する。
- `HealthCheckUseCase`: ヘルスチェック有効化と LINE 送信設定を参照する。
- `CalendarGateway`: カレンダー ID、外出キーワード、終日予定設定を参照する。
- `NatureGateway`: Nature API トークン、対象デバイス ID または名前を参照する。
- `LineGateway`: LINE アクセストークン、送信先ユーザー ID を参照する。
